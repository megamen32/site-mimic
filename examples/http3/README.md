# http3 — HTTP/3 с браузерным QUIC-отпечатком

Запрашивает URL по HTTP/3 через QUIC с отпечатком Chrome QUIC: ClientHello
формы Chrome QUIC (11 расширений, 3 набора шифров — форма QUIC, не TCP) с
постквантовыми подписями и 0xCA34, и транспортные параметры, снятые с
реального браузера.

```sh
go run .                                        # GET https://example.com/
go run . -url https://vk.ru/ -profile ../profiles/windows-chrome152.json
```

Ожидаемый результат:

```
proto=HTTP/3.0 status=200 bytes=334
```

`HTTP/3.0` в `proto` означает, что соединение действительно было h3: клиент
не откатился на TCP молча.

## Что стоит знать

- **Только Go.** Python- и TypeScript-клиенты ходят через `fetchd`, а он
  говорит по TCP.
- **Нужен UDP/443.** Многие сети его режут, и тогда запрос падает по таймауту.
  Отката на TCP нет намеренно: тихий откат — это уже другой клиент, чем тот,
  которого просили.
- **Тело приходит сжатым.** Профиль повторяет браузерный `accept-encoding`
  (`gzip, deflate, br, zstd`), а stdlib распаковывает только тот ответ, где
  заголовок поставил сам. Это поведение всей библиотеки, не HTTP/3: сначала
  верность отпечатку.
- **Connection id пустой**, где у Chrome 8 байт: uquic генерирует id уже
  после сборки ClientHello, а расхождение с транспортным параметром 0x0f —
  это ошибка рукопожатия. Подробности в `mimic/quic_spec.go`.
